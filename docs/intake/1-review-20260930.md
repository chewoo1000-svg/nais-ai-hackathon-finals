## 우선 발견사항

### 1. 동일 V105 압축본 사이의 변경 누락 위험

전체결과물과 UIUX의 제품 루트는 각각 2,528파일이다. 공통 경로 중 서로 다른 것은 발표·영상·이미지 16파일이며 Python 코드는 같다. 추가보완본과 전체결과물은 공통 경로 14파일이 다르다. 핵심 겹침은 `app.py`, `core/portfolio_workspace.py`, `core/research_agent.py`, `core/research_assistant_ui.py`, `core/research_demo_ui.py`, `core/team_workspace.py`, `tools/case_registry.py`, `tools/change_impact.py`다.

추가보완본에는 참조 파일 8MiB/등록 명세 2MiB 읽기 제한, 선택적 AI 평가 기록, 변경된 주장만 재검산하는 경로와 시험이 있다. 전체결과물/UIUX를 통째로 기준으로 삼으면 이 수정들이 빠질 수 있다. 반대로 추가보완본에는 UIUX의 테마 파일·테마 시험·발표 자산이 없다. **추가보완본의 코드 수정과 UIUX 변경을 파일별로 통합**하는 방식을 권한다. 신규 통합본의 실행 확인은 별도 필요하다.

### 2. 동봉 해시 목록의 최신성 불일치

| 패키지 | 동봉 목록 대조 | 결과 |
|---|---:|---|
| 전체결과물 recovery_manifest | 2,423개 | 15개 해시 불일치, 누락 0개, 목록 외 105개 |
| UIUX recovery_manifest | 2,423개 | 같은 15개 해시 불일치, 누락 0개, 목록 외 105개 |
| 추가보완 recovery_manifest | 2,884개 | 불일치 0개, 누락 0개, 목록 외 1개 |
| 추가보완 MANIFEST | 2,883개 | 불일치 0개, 누락 0개, 목록 외 2개 |

목록 외 파일은 자기 매니페스트·후속 추가 파일 등을 포함하며 자동으로 손상이라고 판단하지 않는다. 첫 두 패키지는 압축 CRC가 정상이어도 기존 해시 목록만으로 현재 내용 검증을 주장할 수 없다. 이번 점검에서는 원본 목록을 고치지 않고 현재 파일 해시를 별도 재계산했다. 세부 불일치 경로는 함께 저장한 JSON에 있다.

### 3. 결측값 정책과 문서 간 모순

심사위원 전략의 개발 항목은 결측 선언이 없으면 기존 동작을 유지하라고 하고, 예상 답변은 선언이 없으면 멈춘다고 서술한다. 최종 요구사항을 하나로 맞춰야 한다. 실제 `tools/independent_replay.py`는 `missing_values=['']`만 지원하고 다른 목록을 거부한다. 한편 `core/normalization.py`는 NA 등 추가 토큰을 이미 처리한다. 따라서 ‘전체 엔진이 NA를 전혀 처리하지 않는다’고 일반화하지 않고, 등록·제품·독립 재검산 경로의 계약을 함께 확인해야 한다.

### 4. AI 비평 상세 전달

`core/research_agent.py`의 비평 문제는 일반 결과에서 `CRITIC_UNSUPPORTED` 코드로 요약된다. 추가보완본에는 선택적 평가 원출력 기록이 있으나, 사용자에게 안전한 보완 사유와 다음 행동을 연결하는 기능과는 구분해야 한다. 자유 문장을 실행 명령이나 사람 승인으로 사용하지 않는다.

### 5. 실행·복원 환경

준비본은 Python 3.13 및 고정 의존성을 요구한다. 이번 환경은 Python 3.12.14이고 pytest·Streamlit·SciPy·statsmodels 등이 없으며 pandas/NumPy 버전도 다르다. 전체 회귀시험은 미실행이다. Windows 긴 경로로 일반 복원이 실패하는 항목도 있어 점검 도구에서 확장 경로로 읽었다. 실제 개발용 복원은 짧은 경로와 독립 환경을 권한다.

### 6. 과거 검증 수치·발표 자료의 혼재

문서에는 서로 다른 시점의 테스트 수와 가상 점수가 남아 있다. 추가보완본 FINAL_RECEIPT의 1,578 통과는 과거 실행이며 현재 전체시험 결과가 아니다. 5쪽·7쪽 발표본과 전략의 16과제 비교 설명이 함께 있으므로 최종 발표에는 실제 선택한 시험·시연·버전과 대응하는 수치만 넣는다. 기존 배포 주소와 예전 저장소는 이번 본선 fork 배포를 뜻하지 않는다.

## 이후 개발에서 유지할 우선순위

1. 출처와 실제 반영 시각을 기록한 본선 코드 기준선 구성. 중복 버전 덮어쓰기 방지.
